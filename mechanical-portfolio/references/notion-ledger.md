# Notion 모델 거래 원장

## 운영 모델과 원본

허브 `기계식 포트폴리오 · 운영 허브`의 주소록에서 `trades.dataSourceId`와
`trades.activeModelId`를 읽는다. 연결·워크스페이스·스키마 확인은
[종가 저장 계약](notion-closes.md)의 ntn 우선, Notion 플러그인 폴백을 따른다.
DB 이름은 **`기계식 포트폴리오 · 거래 원장`**이며 같은 계약 표식을 쓴다.
현재 모델 ID는 주소록의 실제 등록값을 사용하고 다른 모델의 행을 합산하지 않는다.
개별 사용자의 모델 ID·초기 자금·시작일·보유 기간을 배포용 지침에 고정하지 않는다.

연속 보유나 현금 대기 제외를 지정한 재현 모델은 운영 기준에서 초기 자금과
출발 이벤트, 보유 구간, 구성 전환일, 제외할 원본 이벤트 ID를 읽는다.
사용자 지시와 저장된 근거가 없는 보유 가정이나 월간 매매를 새로 만들어 넣지 않는다.

구성 전환일에는 이어진 보유 수량과 현금을 확인된 동일 세션 가격으로 평가한다.
그 평가금액으로 지정한 새 구성의 동일가중을 맞춘다. 전량 신규 매수를 그대로 붙이거나
초기 자금을 다시 입금하지 않는다. 보유 종목의 순매도를 먼저 반영하고 필요한
순매수만 계산한다. 이후 기록된 종목 변경·비중 조정의 날짜와 구성을 유지하며
수량은 이어진 모델 자금으로 다시 계산한다. 날짜만 있는 원본에 정확한 체결 시각을
꾸며 넣지 않는다. 일반적인 향후 운영에는 스킬의 월간 첫 거래일 규칙을 적용한다.

가정 모델의 결과는 **사용자가 지정한 가정에 따른 원장 재현**으로 표시한다. 실제 증권사 주문·체결이나
당시 전체 시장 자료로 검증한 전략 백테스트라고 부르지 않는다. 수정 전 원본과
원본 이벤트 ID, 원본 해시, 제외한 이벤트를 보존한다. 원본의 NAV 스냅샷은 이 모델의
성과와 맞지 않으므로 이관하지 않고 새 원장의 수량·현금·확인한 종가로 NAV를 계산한다.
현재 기피 설정으로 적용 시작 이전의 거래를 소급 삭제하지 않는다.
원장 이관은 원본의 현금·수수료 관례를 유지하며 별도 배당 현금·세금 이벤트를
추정해서 넣지 않는다. 총수익 성과를 계산할 때는 실제 기업행동·배당 현금 또는
동등한 조정 시계열을 별도로 검증하고, 배당 이중 계산과 누락을 점검한다.

## 스키마와 키

한 행은 한 모델의 거래, 입출금, 또는 운영 기준이다.

| 속성 | Notion 타입 | 의미 |
|---|---|---|
| 이름 | title | 거래일·종목·구분 또는 운영 기준 |
| 기록 키 | rich_text | 모델 ID와 이벤트 ID |
| 모델 ID | rich_text | 독립 원장 식별자 |
| 이벤트 ID | rich_text | 재실행에도 같은 불변 ID |
| 원본 이벤트 ID | rich_text | 연결한 원본 이벤트 ID 목록 |
| 미국 거래일 | date | 미국 날짜만 |
| 이벤트 시각 | date | 확인된 실제 기준 시각만; 시간대 포함 |
| 이벤트 유형 | select | 거래, 입출금, 운영 기준 |
| 매매 구분 | select | 매수, 매도, 입금, 출금, 모델 전환 |
| 거래 목적 | select | 초기 구성, 월간 비중 조정, 종목 교체, 구성 전환·비중 조정, 종목 교체·비중 조정, 입출금, 운영 기준 |
| 종목 식별자 | rich_text | 확인한 EXCHANGE:TICKER; 비종목 행은 비움 |
| 티커 | rich_text | 심볼 |
| 수량 | number | 거래 수량; 운영 기준은 비움 |
| 단가 | number | 거래 가격; 운영 기준은 비움 |
| 금액 | number | 현금 증가 양수·감소 음수, 수수료 포함 |
| 수수료 | number | 확인된 비용; 임의 추정 안 함 |
| 통화 | select | USD |
| 기록 성격 | select | 원본 기록 이관, 연속 보유 모델 |
| 가격 기준 | select | 원본 기록 가격, 정규장 시가, 해당 없음 |
| 이벤트 묶음 | rich_text | 날짜·확인 시각·목적 등 사람이 읽는 이벤트 이름 |
| 이벤트 묶음 ID | rich_text | 같은 리밸런싱·교체에 속한 세부 거래의 불변 공통 ID |
| 데이터 메모 | rich_text | 가정, 원천 차이, 합산 근거, 미확인 시각 |
| 출처 URL | url | 실제 가격 근거 URL이 있을 때만 |

키는 `모델 ID|이벤트 ID`다. 원본 이관은 원본 이벤트 ID를 유지한다. 새 모델 거래는
모델 ID·거래일·심볼·방향에서 결정되는 ID를 사용한다. 같은 키의 행이 이미 있으면
수량·가격·현금 영향·원본 연결을 비교한다. 동일하면 그대로 두고, 값이 다르면
충돌을 해결하기 전에는 덮어쓰지 않는다. 응답이 불확실하면 정확한 키를 먼저 읽는다.

운영 기준 행은 모델 가정과 제외 이벤트의 근거이며 수량·현금 합산에서 제외한다.
거래의 매수는 수량을 늘리고 현금을 줄이며 매도는 반대로 처리한다. 외부 자금은
입출금 행만 반영한다. 동일 묶음은 매도 후 매수로 재현하고 묶음 뒤 음수 보유·
미지원 차입·중복 외부 자금·중복 키가 없는지 확인한다. 정확한 시각이 있는 이벤트는
그 시각과 순서를 우선하며 날짜만 있는 거래에 일중 순서를 주장하지 않는다.

## 리밸런싱을 기록하는 방식

리밸런싱의 실제 수량·현금 변화는 각 종목의 매수·매도 행으로 기록한다.
매매 구분은 방향이고 거래 목적은 이유다. 월간 비중 재조정은 `월간 비중 조정`,
한 종목의 순위 이탈 교체는 `종목 교체`로 구분한다. 구성 변경과 동일가중을 함께
수행한 명시적 모델 전환은 `구성 전환·비중 조정` 또는 `종목 교체·비중 조정`이다.
순위 이탈 교체를 이유 없이 전체 종목의 비중 재조정으로 바꾸지 않는다.

한 리밸런싱에 속한 매도·매수는 같은 `이벤트 묶음 ID`와 표시 이름을 쓴다.
미래 이벤트 ID는 모델·관측 시각·이벤트 종류·확인한 개별 실행을 구분한다.
같은 날짜에 서로 다른 리밸런싱·교체가 있으면 날짜만으로 합치지 않는다.
시각 없이 같은 가격으로 반복 기록된 조정을 최종 구성 순거래로 통합하려면
등록 모델의 명시적 재현 정책을 확인하고 원본 ID 전체를 연결한다.

Notion **`리밸런싱 기록 · 날짜별 묶음`** 보기는 위 비중 조정 목적을 필터하고
`이벤트 묶음`으로 그룹화한다. 한 번의 조정에 포함된 종목·방향·수량·가격·현금
영향을 펼쳐 볼 수 있다. 같은 원장 행을 보여 주므로 별도의 원장에 매수·매도를
복제하지 않는다. `종목 교체 기록` 보기에는 유지 종목 비중을 바꾸지 않은 교체와
명시적으로 비중 조정을 함께 수행한 교체를 목적별로 구분해 표시한다.

확인한 목표 비중과 기존 비중이 같아 수량 변화가 전혀 없으면 거래를 꾸며 만들지
않는다. 기록이 요청된 정기 조정은 `이벤트 유형=운영 기준`, `거래 목적=월간 비중 조정`의
확인 행으로 남기고 수량·단가·금액은 비운다. 같은 묶음 ID, 기준 시각, 확인한 목표
비중과 `매매 없음` 이유를 메모에 보존한다. 운영 기준 행은 현금·수량 합산에서 제외한다.

## 로컬 및 Work

Notion 등록 모델을 지속 원장으로 사용한다. 로컬에서는 이 모델의 호환 사본을
프로젝트의 `<등록 모델 디렉터리>/position_log.jsonl`에 보존한다.
원본 비교 자료의 위치는 프로젝트 설정에서 확인하고 모델 사본과 합산하지 않는다.
조회·보고서 요청에서는 모델 원장의 전후 해시도 확인한다. 원본 파일이 아직 있다고
그것을 현재 운영 모델로 자동 채택하지 않는다.

기존 CLI를 사용할 때는 현재 도움말에서 `--base-dir` 지원을 확인하고 모델 디렉터리를
명시한다. CLI의 기본 `portfolio` 디렉터리로 연속 보유 모델 성과를 계산하지 않는다.
Work에는 Mac 경로가 필요 없다. 같은 Notion 주소록과 모델 필터로 이벤트를 읽고
표준 필드로 정규화한다. 원장 전체 조회의 커서를 끝까지 읽어야 확정 보유를 계산한다.
모델 ID·거래일 범위로 제한된 조회를 사용하며 다른 DB를 전체 스윕하지 않는다.

`scripts/mechanical.py continuous-ledger`의 입력·제약은
[헬퍼 계약](helpers-and-local.md)을 따른다. 원장 설치·이관이 요청된 경우에만 모델
생성 결과를 실제 저장하고 ID·키·금액을 읽어 확인한다. 보고서 실행마다 모델을
새로 생성하거나 원본 기록을 다시 삽입하지 않는다.
