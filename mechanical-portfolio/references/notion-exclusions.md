# Notion 기피 종목과 적용 이력

## 사용자가 관리하는 설정

전용 DB 이름은 **`기계식 포트폴리오 · 기피 종목`**이다.
허브 주소록의 `exclusions.dataSourceId`로 연결하고 같은
`Mechanical Portfolio storage contract: mp-notion-v1` 표식을 사용한다.
연결 선택·이름 탐색·워크스페이스·ID·스키마 확인은
[Notion 저장 계약](notion-closes.md)을 따른다.

현재 기피 목록은 이 DB에서 읽는다. 뉴스, 모델의 호불호, 가격 하락을 근거로
종목을 자동 추가하지 않는다. 사용자의 지정 DB 입력은 전략 설정으로 읽으며
실제 증권사 주문이나 매매 원장 변경의 허가로 확대하지 않는다.
사유에 담긴 사실을 별도 검증 없이 기업에 대한 현재 사실로 보고하지 않는다.

허브에는 사용자가 읽을 수 있는 다음 안내를 둔다.

1. **추가:** 새 행에 티커를 넣고 상태를 `제외`로 선택한다. 사유는 선택 사항이다.
   적용 시작을 비우면 그 행의 실제 등록 시각부터 적용한다.
2. **해제:** 기존 행에 적용 종료 시각을 넣고 상태를 `해제`로 바꾼다.
   과거 적용 기간을 보존하기 위해 행을 삭제하지 않는다.
3. **재추가:** 해제한 행을 덮어쓰지 않고 새 적용 기간의 행을 추가한다.
4. **대기:** 아직 제외하기로 결정하지 않은 종목은 `대기`로 둔다.
   다음 실행에서는 해당 행으로 편입을 막거나 기존 보유를 매도하지 않는다.

당시 기록이 없는 과거 적용일을 추측하지 않는다. 날짜만 있는 수동 입력은
KST 00:00의 유효 시각으로 정규화하고 그 해석을 안내한다.

## 스키마

| 속성 | Notion 타입 | 의미 |
|---|---|---|
| 이름 | title | 회사명 또는 티커; 사람이 읽는 이름 |
| 제외 키 | rich_text | 확인한 공통 식별자와 시작 시각으로 만든 기간 키 |
| 티커 | rich_text | 사용자가 넣는 티커; Yahoo/TradingView 표기를 확인해 대응 |
| 종목 식별자 | rich_text | 확인한 공통 EXCHANGE:TICKER |
| 상태 | select | 제외, 해제, 대기 |
| 적용 시작 | date | 시간 포함 권장; 비우면 실제 등록 시각 |
| 적용 종료 | date | 시간 포함 권장; 종료 시각부터 제외하지 않음 |
| 사유 | rich_text | 사용자의 선택 사항 |
| 설정 출처 | select | 사용자 입력, 기존 설정 이관 |
| 출처 URL | url | 사용자가 남긴 참고 근거; 선택 사항 |
| 등록 시각 | created_time | 실제 최초 등록 시각; 수정으로 바꾸지 않음 |
| 최근 수정 시각 | last_edited_time | 화면 점검용; 적용 시작/종료를 대신하지 않음 |

사용자는 이름·티커·상태·사유·시작·종료를 주로 편집한다. 식별자와 제외 키는
확인한 심볼 매핑으로 채운다. 이름만 보고 모호한 종목을 특정하지 않는다.
티커가 확인되면 회사명 표시를 보완할 수 있지만 사용자 사유·기간은 보존한다.
`등록 시각` 속성이 없으면 실제 페이지의 불변 `created_time`을 읽는다.
현재 도구가 지원하는 생성 타입을 확인하고 선택/날짜를 텍스트 속성으로
대체해 정상 스키마라고 부르지 않는다.

기간 키는 `종목 식별자|시간대가 있는 적용 시작 시각`이다.
입력 시각은 UTC로 정규화해 키를 계산하고 사람이 보는 시각은 KST로 표시한다.
동일 종목을 다시 제외한 경우에도 종료된 과거 기간을 덮어쓰지 않는다.
등록된 DB에 새 행을 쓰기 전에는 그 종목의 열린 기간을 좁게 조회한다.
동일 기간이면 재사용하고 겹치는 중복은 알려주되 임의 삭제하지 않는다.

## 최초 설치와 기존 설정

새 스킬의 첫 저장소 설치는 허브, 종가 DB, 기피 DB와 요청된 거래 원장을 만들고
필요한 데이터소스의 실제 ID와 스키마를 읽어 주소록에 등록한다. 일반 실행에서 구조를 바꾸지 않는다.
이미 있는 허브에 기피 DB가 없으면 현재 요청에 설치가 포함됐는지 확인한 뒤
이름 탐색·설치 절차를 적용하고 정상 읽기와 구조 변경을 구분한다.

기존 사용자 설정을 이관하는 첫 설치에서는 확인한 수동 제외 목록만 한 번,
`설정 출처=기존 설정 이관`으로 기록한다. 실제 과거 적용일이 없으면 이관 시점을
시작으로 두고 그 이전 백테스트에서 적용 이력은 미확인으로 남긴다.
배포본에는 개인별 기피 목록을 포함하지 않으며 신규 사용자 전략에 강제로 심지 않는다.

DB가 등록된 뒤에는 **빈 활성 목록도 유효한 설정**이다. 기존 상수를 매 실행마다
되살리거나 사용자가 해제한 종목을 다시 추가하지 않는다. 사용자 지정의 일시적
제외/해제는 이번 실행에 우선하되, DB 변경은 사용자가 저장을 요청한 경우에 한다.

## 실행 시 해석

1. 등록 데이터소스의 현재 스키마를 읽고 범위에 해당하는 설정 행을 전부 조회한다.
   커서/`has_more`를 끝까지 확인한다. 기본은 허브의 기계식 전략 전체에 공통 적용이다.
   여러 전략의 다른 목록이 필요하면 사용자 지정 범위 계약을 먼저 추가한다.
2. 심볼을 공통 식별자와 랭킹용 티커에 대응시킨다. 주식 클래스·ADR·같은 이름의
   다른 거래소 종목을 확인한다. 미해결 입력을 조용히 버리지 않는다.
3. `제외/해제` 행은 `[적용 시작, 적용 종료)` 기간으로 해석한다.
   시작이 비어 있으면 불변 등록 시각을 사용한다. 상태 `해제`에는 종료가 필요하다.
   시작 전에 끝나는 기간, 미해결 티커, 종료 없는 해제는 자료 확인 필요다.
   예정 종료일이 미래이면 종료 전까지 계속 제외하며 이를 화면 안내에 표시한다.
4. 현재 순위에는 **순위 관측 시각**에 유효한 제외를 적용한다. 역사 백테스트에는
   각 과거 판단 시각에 유효한 기간만 적용한다. 오늘의 목록을 과거 전체에 복사하지 않는다.
   상태 `대기`는 어느 쪽에서도 제외로 적용하지 않는다.
5. 여러 기간이 같은 종목에 겹치면 제외 집합에는 한 번만 넣고 중복 페이지를
   보고한다. 서로 다른 식별자가 같은 티커로 대응되면 충돌을 먼저 해결한다.
6. 완전하게 읽은 집합을 `rank`와 `decision-plan`의 **같은 `exclusions` 인자**로
   전달한다. `FinalRank`는 제외 적용 전 순위이고 신규 편입은 제외를 건너뛴다.
   기존 보유의 유효한 수동 제외는 교체 조건이며 관측 이후 정규장 시가 규칙을 따른다.

`scripts/mechanical.py resolve-exclusions`가 기간 해석을 지원한다.
조회 실패·누락·잘못된 기간으로 완전성을 확인하지 못하면 기피 목록을 0개로
취급하지 않는다. 랭킹 원천 수치와 보고서 초안은 만들 수 있지만 신규 편입·교체를
확정하지 않는다. 마지막 확인 스냅샷이 있으면 시각과 잠정 상태를 명시한다.
헬퍼 결과의 `effective_complete=true`와 실제 전체 조회 근거를 모두 확인한다.

## 쓰기와 읽기 확인

추가/해제 요청에서는 지정 종목·상태·기간·사유만 변경한다. 해제한 행과 관련
뉴스·사유를 삭제하지 않는다. 관측시각이 없는 사용자 입력을 뒤로 소급하지 않는다.
응답의 실제 페이지 ID/URL과 적용 값을 확인하고, 새 행·배치·불확실 응답은
한 번 읽어 확인한다. 정상 보고서 실행에서 입력 사유나 유효 기간을 다시 쓰지 않는다.
가격 조회 성공, 기피 설정 읽기 성공, 종가 저장 성공은 각각 다른 상태로 보고한다.
