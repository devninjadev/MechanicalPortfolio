## 성과 계산

실제 원장 기반 재현은 각 시점의 보유 수량과 현금, 실제 기록 이벤트,
정규장 가격으로 `NAV_t = cash_t + sum(q_i,t * price_i,t)`를 계산한다.
외부 입출금이 있으면 가격 성과와 자금 유입을 분리한다. 일별 시간가중 수익률은
현금 흐름 시점을 반영하며 단순 NAV 비율을 그대로 투자 수익으로 부르지 않는다.

시작점은 이번 요청의 지정일·세션을 우선한다. 지정이 없으면 사용자의 개인 설정과
등록 모델의 성과 기준을 읽고, 기준이 없으면 해당 모델의 실제 개시 이벤트를 사용한다.
개인별 기본 날짜나 모델 ID를 배포용 지침의 상수로 넣지 않는다.
시작점 이전의 원장은 그 시점의 보유·수량·현금을 재구성하는 데 사용하며,
성과 시작일에 초기 자금을 다시 입금하지 않는다. 시작 시점 평가액을 성과 지수
100으로 정규화하고 벤치마크도 같은 날짜·세션·가격 기준에서 시작한다.
신규 모델에는 기존 사용자의 시작점을 적용하지 않고 그 모델의 실제 개시 이벤트를 읽는다.

모델 전략 백테스트는 당시 유니버스·재무 발표 시점·수동 제외의 유효일·매매
이벤트 시각을 반영한다. 최신 순위나 현재 보유 종목을 과거에 적용한 고정 바스켓
시뮬레이션은 그 이름과 생존 편향·미래 정보 사용 한계를 명시한다.

주식분할·배당·티커 변경과 원장 수량을 일관되게 처리한다. 주가 성과와 배당 포함
총수익률을 혼합하지 않는다. 비용·세금·환율·배당을 제외하면 본문에서 밝힌다.
벤치마크는 사용자가 지정한 것을 정확히 쓴다. 기존 기본 후보는
`SPY, QQQ, IWM, SCHD, QLD, IVES, SPMO, FNGS`이며 다른 지시가 있으면 그 지시를 따른다.

프리마켓 요청이면 마지막 잠정 점을 별도로 표시할 수 있다. 위험 통계는 마지막
완료 정규장 종가까지만 계산한다. 전일 종가를 오늘의 가격으로 전방 채운
행은 관측 성공·0% 변동으로 집계하지 않는다. 미확인 자산이 있으면 평가 범위와
마지막 확인 가격을 명시하고 충분한 데이터가 없는 통계는 미확인으로 둔다.

본문 표에 누적 수익률, 연환산 수익률, 최대 낙폭, 변동성, Sharpe, Sortino,
Kelly, Ulcer Index, UPI, Beta를 표시한다. Beta는 기본 SPY이며 요청에 따라 바꾼다.
[성과 계산 계약](performance-math.md)의 평가·자금 흐름·분할·표본·통계 정의를
적용한다. 계산법과 기간을 명시하고 비율의 분모가 0이면 미확인으로 표시한다.

## 그림 한 장

백테스트/원장 기반 성과 곡선과 모든 지정 벤치마크를 하나의 PNG에 그린다.
실제 재현이면 차트 제목도 그 의미를 따른다. 별도 통계 PNG·낙폭·기여도 그림은
기본 생성하지 않는다. 기존 CLI의 자동 통계 이미지 출력은 이 기본값을 대체하지 않는다.

우측 끝에 `자산명 (오늘 수익률%) | 총 수익률%` 라벨을 붙이고 각 값은 소수점
둘째 자리까지 쓴다. 휴장일에는 마지막 거래일 기준임을 표시한다.
라벨은 흰 글자, 선과 같은 배경색을 쓰고 겹치지 않도록 세로 보정한다.
포트폴리오 선은 두껍게, 비교 선은 얇게 한다. 전체 고저점과 라벨 위치를 반영해
Y축을 넓히고 저장 시 충분한 패딩과 `bbox_inches="tight"`를 사용한다.
공통 구간 밖의 결측을 임의로 연결하지 않는다. 최종 PNG를 열어 잘림·가독성과
최종 수익률이 본문 수치와 맞는지 확인한다.

## 페이지 본문

새 페이지 제목 예: `2026년 9월 30일 기계식 포트폴리오 점검`.
사용자가 지정한 Page/Space/부모가 있으면 먼저 읽고 적용한다.
분석할 유효 데이터가 있고 대상이 없으면 개인 페이지를 생성한다. 현재 보이는 페이지가 없다고 위치를
재질문할 필요는 없다. 특정 대상에 같은 목적의 보고서가 있으면 읽고 재사용한다.
기존 페이지는 이번 요청 범위만 수정하고 사용자 편집·댓글을 보존한다.

페이지는 데이터와 분석 보고서다. 본문 도입문에는 분석 결론과 기준 시각을 짧게 쓴다.
도입문 바로 다음 첫 섹션에 성과 곡선을 배치한다. 원장 기반 보고서는 첫 섹션 제목을
`원장 기반 성과 곡선`으로 쓰고, 그 아래에 포트폴리오와 지정 벤치마크의 곡선 이미지
한 장과 계산 가정을 둔다. 보유 종목·순위·매매 판단·성과 통계 등 다른 섹션을
도입문과 성과 곡선 섹션 사이에 넣지 않는다. 모델 백테스트나 고정 바스켓
시뮬레이션의 섹션 제목은 실제 계산의 성격에 맞추되 같은 위치에 배치한다.
그 이후에 필요한 다음 내용을 포함한다. 기간에 따라 분량은 조절하며 제목을 본문 H1으로 반복하지 않는다.

- 기준 미국 거래일과 KST 표시, 가격 세션, 순위 자료의 기준 시각.
- 현재 보유/신규 후보와 순위, 목표·현재 비중, 판단에 필요한 데이터 범위.
- 관측 시점의 수동 기피 종목과 적용일, 선정 결과에 미치는 영향.
- 월간 비중 조정과 순위 이탈 교체를 구분한 판단, 대기 체결 시점.
- 포트폴리오와 벤치마크의 성과·위험 수치 표.
- 실제 계산에 사용한 출처, 가격·분할·배당 기준, 결측이 분석에 미치는 영향.
- 마지막 섹션 **`결론`**.

결측이나 불완전한 표본을 숨기지 않는다. 다만 페이지에는 영향을 받는 종목·기간·통계와
잠정값의 해석 한계만 쓴다. 예: `일별 시계열이 없어 최대 낙폭과 변동성은 산출하지 않았다.`
P/S를 시가총액/매출로 구했다면 같은 관측 시점·통화의 입력값과 계산법을 남긴다.

연결 오류·접근 거절·재시도·폴백의 진행 과정, 테스트 통과 여부, 저장 건수·실패,
업로드·삽입·렌더링 확인, 승인 요구는 채팅에만 쓴다. `작동 확인`, `연결 문제`,
`실행 결과` 같은 운영 섹션을 페이지에 만들지 않는다. 마지막 `결론`도 포트폴리오의
분석과 매매 판단으로 끝낸다. 전체 제공자 원시 응답·파일 목록·내부 작업 코드는 넣지 않는다.
뉴스·월드 메모리 해석을 추가해도 기계식 규칙과 구분한다.

## 채팅의 실행 안내

페이지 링크와 핵심 매매 판단을 먼저 안내하고 필요한 실행 상태만 짧게 덧붙인다.
조회·저장·발행의 성공과 실패를 구분하되 실패를 보고하는 데서 멈추지 않고 승인된
대체 경로로 가능한 작업을 계속한다. 드라이런의 테스트·연결 점검 결과도 채팅에 쓴다.
유효한 분석 결과가 전혀 없으면 상태와 남은 필요 조건을 채팅으로 알리고 새 페이지를
만들지 않는다. 부분 결과가 있으면 그 분석만 발행하며 오류 일지를 덧붙이지 않는다.

## 네이티브 이미지 발행

현재 ChatGPT Pages 도구의 create/read/edit/write reference 기능을 탐색한다.
`pages:write-page`가 있으면 그 현재 지침을 따른다. 없어도 아래 계약은 자체적으로
사용할 수 있다. 제목·본문은 기본 편집 가능한 Markdown 블록으로 쓴다.
사용자가 **이미지**를 지정했으므로 이 작업에서 HTML/Visualize로 대체하지 않는다.

1. 보고서 Page를 생성하거나 대상 Page를 읽는다. 반환 Page ID와 URL을 보존한다.
2. 실제 PNG 파일을 `write_page_reference(page_id, file=호스트의 절대 파일 경로)` 등
   현재 업로드 도구로 올린다. Work에서는 그 실행기가 반환한 실제 파일을 사용한다.
3. `file_access_confirmed=true`, `is_image=true`, 파일 참조와 `markdown`을 확인한다.
   업로드는 삽입이 아니다. 반환한 `![...](project-file:...)` 또는
   `![...](library-file:...)`를 그대로 보존한다. 참조 ID를 만들거나 외부·로컬·data
   URL을 네이티브 이미지인 것처럼 저장하지 않는다.
4. 최신 페이지 읽기에서 얻은 블록 ID·해시·시퀀스·stream_kind를 사용해
   도입문 바로 다음 첫 성과 곡선 섹션에 이미지 Markdown을 독립 블록으로 삽입한다.
   Page 편집 도구의 현재 스키마를 따른다. 삽입 위치의 양쪽 이웃도 실제 읽기에서 얻는다.
5. 모든 편집 결과의 적용/거절을 검사하고 새/대폭 수정된 페이지를 읽어 확인한다.
   도입문 다음 첫 섹션이 성과 곡선이며 해당 섹션에 차트가 삽입됐는지 확인한다.
   미리보기가 있으면 차트 로딩·제목·표·잘림을 확인한다. 없으면 저장/참조 삽입까지
   검증했다고 채팅에서 밝히며 렌더링은 미확인으로 둔다. 이 상태를 페이지 본문에 넣지 않는다.

동일 보고서를 다시 발행할 때는 본문·기존 이미지 참조를 읽고 필요한 블록만
수정한다. 업로드 성공/삽입 실패는 반환 참조를 재사용한다. 결과가 불확실하면
Page/Files를 확인하고 새 페이지·새 이미지 업로드를 무작정 반복하지 않는다.
페이지 기능이 없으면 본문은 채팅으로 제공하고 페이지 발행 미완료를 알린다.
기본 `.md`·ZIP 배포로 되돌리지 않는다.
